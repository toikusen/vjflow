# 新增歌曲：放進音檔就看到影片（2026-11-03）

使用者決定：拿掉「上傳並準備」彈窗；選好音檔、貼好歌詞就直接出免費影片；上傳與時間校準在背景；歌曲可以刪除、改名。不要照抄 JIZURA，要直覺。

## 對象與主要任務

做歌詞影片的人：自己寫歌、唱歌或用 AI 做歌的創作者，手上有一個音檔和一份歌詞（常是從別處貼來，帶 `[Verse]`、`# 標題`）。主要任務：**從一個音檔到看見自己的歌詞影片，幾秒內完成**，其餘（上傳、對時間）都不需要他們管。

## 設計決定

沿用平台現有的設計系統（深色、`--accent #ff6a4d`、Unbounded 與 Noto Sans TC），這是既有產品裡的一個流程，一致比新奇重要。唯一刻意強調的地方是**畫面本身**：

- **畫面就是放歌的地方**。不用一般的虛線上傳框；空的 16:9 畫面就是拖放區，裡面淡淡地播著一段歌詞動態示範，中央一行「把音檔拖到這裡」與「選擇音檔」。音檔放進去，同一塊畫面變成影片。理由：使用者要的是影片，讓第一個動作就落在影片會出現的地方。
- **歌詞像一張歌詞紙**：左邊一欄高的文字區，貼上即可；自動辨識 `# 標題`（填進歌名）與 `[段落]`（灰掉標示「不會出現在影片」），讓人看懂哪些行會變成字幕。
- **一條狀態帶取代彈窗與說明文字**：畫面下方一行，依序點亮三格（這是真的順序）：`上傳 62%` → `已存到我的歌曲 · 對準歌詞時間中，約 17 分鐘` → `時間已對準，可以匯出`。

## 版面

桌面（≥ 1100 px）

```
┌ 歌詞 ──────── 340 px ─────────┬──────────────── 畫面 ──────────────────┐
│ ┌──────────────────────────┐ │ ┌─────────────── 16:9 ───────────────┐ │
│ │ 貼上歌詞                   │ │ │ 空：淡淡的示範動態                  │ │
│ │ [Verse 1]  ← 灰：不會出現  │ │ │     把音檔拖到這裡  ／ 選擇音檔      │ │
│ │ 朝からアラーム…            │ │ │ 有音檔沒歌詞：波形 + 「貼上歌詞就能看到」│ │
│ └──────────────────────────┘ │ │ 兩者都有：影片                       │ │
│ 歌名  [自動：# 標題或檔名]     │ └────────────────────────────────────┘ │
│ 歌手  [選填]                   │ ▶ 0:12 / 3:24 ━━━━━━  風格：水墨（推薦） │
│ 語言  [自動辨識 ▾]             │ [換一版]   [匯出 720p]                   │
│                                │ ●上傳 62% ─ ○對準時間 ─ ○可以匯出        │
│ 只上傳你有權使用的音樂          │ 風格（橫向一排卡片）                     │
└────────────────────────────────┴────────────────────────────────────────┘
```

手機（< 720 px）：畫面在最上（點一下選音檔），狀態帶、播放列、風格橫排，歌詞區在下面。

## 行為

1. 音檔先或歌詞先都可以；兩者都有就在瀏覽器裡用本機音檔立刻產生影片（免費版現有的估時間方式），不等上傳。
2. 歌名自動帶入（`# 標題` 優先，否則檔名去掉副檔名），語言依歌詞文字自動判斷（假名→日文、韓文字→韓文、漢字→中文、其他→英文），都可以改。
3. **自動存檔**：音檔、歌詞、歌名都有，且歌詞停止修改 4 秒後，自動建立歌曲並在背景上傳（有進度）。不需要按鈕。存好後網址換成 `/my/song?id=…`（`history.replaceState`），畫面不中斷；之後歌詞欄變唯讀，旁邊一個「修改歌詞」連到現有的時間編輯器。
4. 上傳還沒完成就要離開，才用瀏覽器原生的離開提醒。上傳失敗：狀態帶顯示原因和「重試」。
5. 校準完成（輪詢 `/beta/songs`）後，畫面自動換成伺服器對好的時間，匯出解鎖。校準前匯出按鈕保持停用並說明原因（沿用 `exportHold`）。
6. 歌曲列表頂端一個主要動作「做一支新影片」，打開這個畫面；列表與舊的 composer 表單合併為這一個入口。

## 刪除與改名

- 歌曲頁標題可直接點擊改名（Enter 存、Esc 取消），伺服器 `PATCH /beta/songs/:id { title }`。
- 「刪除歌曲」放在歌曲頁的更多選單裡，用現有確認視窗（這是不可逆的動作，值得一次確認）：「刪除後，這首歌和它的影片都會從你的列表消失。」伺服器 `DELETE /beta/songs/:id`：**軟刪除**（`deletedAt`，列表與 API 不再出現；檔案搬到 `out/beta/deleted/<id>`，不真的刪），有工作在排隊或製作中時拒絕。費用紀錄不受影響。
- 拿掉「歌曲建立後不能刪除或改名」的說明文字。

## 文字

主要動作的用詞一路一致：「做一支新影片」→ 狀態帶的「已存到我的歌曲」→ 歌曲頁。錯誤說明原因和下一步，不道歉。
