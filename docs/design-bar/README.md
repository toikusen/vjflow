# Design bar — 12 條強制驗收 + 判決卡

來源：`docs/research/2026-11-09-taste-codex.md`（Codex × Claude 討論，2026-11-09）。
業主決定：先建 12 條規則與判決卡系統；不找真人設計師。

這份文件是**驗收契約**，不是風格指南。每個世界的「品味」仍由 `world-shared.ts`
與各世界檔案決定；這裡只規定什麼情況算退回。

## 用法（三個時機）

| 時機 | 做什麼 |
|---|---|
| 生成前 | `npx tsx scripts/lyric-vj/verdicts.mts pack --world <id> [--rule N]` 取全域硬傷卡 + 約 2 接受、2 拒絕、1 邊界（含其配對），連同圖像路徑放進 brief；critic 必須實際讀到圖／短片，路徑不算證據。生成者先寫一行「沿用哪個關係、避開哪個失敗」，才動手。 |
| 實作中 | 12 條逐項自查；任一條退回即停，不靠加材質續命。 |
| 驗收時 | critic（新上下文，見下方格式）只拿匿名候選＋參考＋相關卡＋核准契約；不拿作者辯護。業主判決落地後立刻寫卡。 |

## 12 條規則

| # | 規則 | 如何檢查 |
|---|---|---|
| 1 | 類型辨識與完成度分開過關 | 隱藏風格名稱，與真實參考、近鄰世界並排；業主能否辨認預期類型？漂亮但認錯仍退回。 |
| 2 | 每個世界只有一個核心設計命題 | 一句話描述歌詞角色；每個主要元素須能連回這句話，否則刪除或說明必要性。 |
| 3 | 核准稿是比例契約 | 記錄字面積、留白位置、主次尺度、對齊軸與視覺重心；用實際歌詞比較引擎靜態輸出，灰階也要成立。 |
| 4 | 字體必須做光學校正 | 繁中、日文、拉丁混排測試字面大小、基線、標點、斷行與直排方向，在實際播放尺寸檢查。繁中字體每款至多三個世界。直排標點、字形方向、禁則依 [W3C clreq](https://www.w3.org/TR/clreq/) 建測試字串。 |
| 5 | 細節有層級，不能靠假資訊填滿 | 大、中、微尺度須有不同任務；再以三種觀看尺度檢查：縮圖看主角，原尺寸看閱讀，200% 看邊緣。微字只能來自真實歌曲內容。 |
| 6 | 色彩是面積與角色，不只是色票 | 宣告底、字、輔助、強調的使用範圍；在實際合成畫面檢查面積主次、閱讀對比與高潮變色。Riso 可從實際油墨組合出發，螢幕結果仍須核准。（ink ≥ 4.5:1 是產品既有的閱讀規則，量於字與其直接底色，不是這條的美學門檻。） |
| 7 | 材質缺陷必須有成因 | 紙紋固定在紙上；錯版作用於色版；滲墨跟著墨邊；厚度與陰影一致。固定時間重算須一致，逐格不能無故爬動。 |
| 8 | 閱讀載體有完整身分 | 每段交接都能指出字屬於哪張紙、哪個物件；接縫沿真實輪廓。禁用膨脹字框截圖補洞；禁用不透明物件的整頁交叉淡化。（seam/mud check：`out/research/enters-1109/seamcheck.mts`） |
| 9 | 動作曲線由材質決定 | 每世界列允許的曲線家族、時長、預備動作與回彈上限；預備動作、回彈預設為零，只有有理由才開。檢查位置／速度曲線及逐格條，不只驗宣告。 |
| 10 | 主次動作不得搶閱讀 | 每個事件只有一個主動作；次動作須延遲、較小幅度並先收尾。檢查閱讀時窗內的晃字、換字面是否干擾辨識或爭奪焦點；干擾閱讀即退回。 |
| 11 | 整首有安靜、發展與爆點 | 做整首縮圖時間軸，檢查鏡頭密度、重複動作與高潮配置；不能每句都表演完整進退場；慢歌另驗。 |
| 12 | 設計必須能承受內容變化 | 固定測快慢歌、長短句、繁中與混排、多種子；先過靜態，再過正式幀率、縮放與壓縮後的動態檢查。 |

硬傷不以總分抵銷：確認載體破裂（8）或讀不清（4/6/10）即退回；證據不足則交業主。critic 是攔錯工具，不是美感裁判：不能僅因方案不尋常而淘汰，要保留合理但有風險的方向。

### 大面積色面（取代 2026-10-31 visual-finish-bar 規則 1「至少兩項質感」；業主 2026-11-09 授權 Claude × Codex 決定）

> 大面積色面應符合該世界已核准設計稿的材質與構圖角色；核准的平塗與留白可直接使用，不設質感種類下限。
> 未有對應平塗核准依據者，須宣告並驗證其角色為 `paper`、`plate` 或 `ground`，不得以無角色色塊補空間。
> 本條優先於一律加纖維、斑駁或陰影的要求；任何材質處理均不得損害閱讀與接縫完整性。

腳本檢查（待校準提案，尚未實作）：連通區占畫面 ≥ 12 %、排除文字與邊緣後區內 95 % 像素與代表色 ΔE00 ≤ 2 → 大平塗候選；有核准平塗依據即通過；有可驗證角色（carrier id、角色遮罩）依該角色檢查；兩者皆無標記待審。不自動加紋理，不以雜訊多寡評分。用已核准的平塗與材質案例校準誤報。

## 判決卡

一張卡 = 一次業主判決。放在 `docs/design-bar/cards/`，檔名 `YYYY-MM-DD-<slug>.md`，格式見 `cards/_template.md`。

原則（Codex Q2）：

1. 業主原話逐字保存；AI 推測的原因另欄標 `inferred`，不得冒充業主理由。
2. `scope: global` 只給業主明說跨世界的底線（例：補丁破壞載體）；`scope: world` 是局部喜好（例：喜歡這張紙紋），不得推成所有世界都要；只談一首歌、一段剪輯的用 `scope: song`，只在 `--song` 符合時檢索。AI 的推廣只能寫在 inferred 或標「推論」。流程規則（如 修正 功能怎麼改）設 `anchor: false`，留存但不進 pack。後續改口不覆寫，新增一張卡並以 `supersedes` 指回。
3. 同世界、同歌詞的修前／修後配對最有價值；用 `pair` 欄互指。不同世界的接受與拒絕不湊成因果。
4. 生成前檢索少量，相關性優先、配額只是例子：適用的全域硬傷卡必帶；其餘按本次規則／失敗機制、歌詞排版條件與載體情境排序，同世界優先，同等相關才取最新；有效前後配對一起取，不為湊數拆散；不足就明示不足（`pack` 會印出「不足」行）。圖像與原話都給。
5. 評分用有圖的錨點：類型、構圖、字體、材質、動態各用「拒絕／邊界／接受」三級。整體接受不代表五個面向都接受；只把業主判決或可見證據支持的面向（`aspects`）當錨點，其餘標未判定。
7. 沒有原話的卡可以保留，但只有 `inferred` 的卡不能當接受／拒絕錨點（`pack` 會跳過它們）；須有可追溯的業主判決紀錄（`source`）。
6. 留一部分卡做盲測（`blind: true`）；同一修訂系列同組；記錄誤放行、誤淘汰、無法判斷；不宣稱小樣本能證明可靠率。

## critic 格式

```
輸入：匿名候選圖／短片、類型參考、相關判決卡、核准設計契約。
任務：先描述可見證據，再與接受／拒絕錨點比較；不得只說「缺少質感」。
輸出：通過／退回／交業主；具體位置或時間碼；最接近的歷史卡 id；前三項修正；不確定處。
成對比較：A／B／平手／皆不合格；交換左右再比較，若改判則標示不穩定。
```

跑法：`codex exec --sandbox read-only -i <strip...> -o <answer.md> "<brief>" </dev/null`，
brief 由 `verdicts.mts pack` 的輸出加上述格式組成（見 `.claude/skills/vj-design-bar/SKILL.md`）。
