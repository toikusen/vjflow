**結論：`planWorldEvents()` 已經接進免費路徑，整首歌只有一張事件表（Q2 hold、Q4 交接、Q1 換座位，每件只算一次），渲染器只鋪表上核准的頁交接。但 45 個世界的中位數沒有往上走：快歌 3.6 → 3.6、慢歌 3.2 → 3.2（計畫層級），影片核對後是 3.2／3.2。五個單頁世界的中位數反而下降（快 3.6 → 3.2、慢 3.2 → 2.8；影片核對後 2.8／2.4）。** 原因：40 個未宣告能力的世界依規則保持原樣；五個單頁世界有四個的座位綁在自己的頁面上，只能在句與句之間換；加上整段的連續換位上限（規則 11）、Q2 hold 的保留區，以及不再用比例時間假造詞界。4.0／6 的目標沒有達到。閱讀閘門 0 失敗、0 退步；Q2 覆蓋率沒有下降。

## 從哪個函式搬出了什麼（Codex B 的拆分）

1. **`compose()` / `reposeOf()`**：已宣告能力的世界，句內切換的時間、次數和跨句仲裁都交給排程器；compose 只留內容排版和 `seatsFor()` 候選。「repose 一定換 ground」只在這條路徑消失：句內切換寫進 `world.repose`，不新增 cut，也不換底。
2. **`composerTreatment()`**：這條路徑上沒有 repose cut，所以 `REPOSE_GAP` 那一支不會被用到。核准的事件由 `applyWorldEvents()` 寫進計畫，composerTreatment 只負責轉譯。`unrepeatGround()` 沒有刪：它只換既有 section 的底紋，不會新增 section，也不會換座位，所以不製造構圖切換（見「決定」第 6 點）。
3. **`linkGrounds()`**：只落實核准的交接。`pickWorldMoves()` 仍是候選來源。
4. **`world-layout.ts build()` / `world-cam.ts`**：直接讀 `wl.set`、`wl.repose`、`wl.cam`。接線後這三個欄位只放排程器核准的值，所以這兩個檔案的繪製程式不必改（`world-layout.ts` 只加了 `seats` 型別欄位）。
5. **`engine.ts`**：收一張完整的事件表。

## 決定（Codex 文件沒寫到的地方，一律選保守做法）

1. **未宣告能力的世界（40 個）完全維持原樣**：沿用 composer 的 repose 和換底，排程器只把它們登記成 given／pinned 寫進事件表，不做任何自己的切換。這是「capability off → keep」最保守的解讀，因此 45 世界的中位數不會因接線而改變。
2. **以下幾種句子的座位是 composer 的（pinned）**：有 Q2 hold 的句子（hold 是在那個 set 上規劃的）、共用 shot 的句子、有 set piece 或 call 的句子、有放大字的句子（句子讀完後才能在句內切換）。
3. **句內切換不換載體**：綁頁的 set 不能在句內換頁，所以 blueprint／notebook／art-deco／document 沒有句內切換。
4. **camera-reframe 只登記 composer 已有的段落進場鏡頭**，排程器不新增鏡頭；**page-handoff 只登記 Q4**，排程器不自己新增。依據是 Codex cap 裁決，以及渲染器還沒有對應的畫法。
5. **chalkboard 的 erase-reseat 和 document 的 feed-advance／tear-next 列為 `pending`**：渲染器還不會畫，所以排程器不排。
6. **`unrepeatGround()` 保留**：它只換底紋，不新增 section，不算切換。換光的 0.55 秒下限仍由 composerTreatment 的 gap 負責。
7. **keep 的意思是沿用前一句的座位**，前提是那個座位也是這一句的合法候選；否則就改用本句自己的座位（記為 warning）。pinned 和這種情況造成的間距衝突照樣保留，寫進 `warnings`，不藏起來。片段內共 87 筆 warnings（`wired.json` 的 `wired.warnings`），分布在 18 列 pinned seat 與 2 列 hold 部分重疊交接；pinned 的多半是未宣告世界原本的 repose 和下一句 seam 間隔不到 0.65 秒（例如 silk c032→c033）。
8. **Composer 自己換了 set 時，只要連續換位上限允許就照用**；排程器只按段落 pace 額外加換位。不過整頁交接只依 pace 決定，不跟著 composer 換 set（規則 11）。
9. **Q3／Q5 的 draft caps（`scale-caps-draft.ts`、`moment-caps-draft.ts`）沒有併進來**：那是另一套政策輸入，併進來不算小事，留給 Q3／Q5 第二階段。

## 還沒解決的

- **高密度構圖沒有解決**：快歌 4.0 是 45 個世界、計畫層級的中位目標。接線後計畫中位是 3.6，影片核對後是 3.2，兩者都沒到；五個單頁世界還下降了。和 JIZURA 的差距仍在。
- 要往上走，需要：其他 40 個世界逐一宣告能力（這次刻意沒做）；渲染器補上 pending 的畫法（erase-reseat、feed／tear）；提高對齊覆蓋率（沒有逐字時間的句子不能做句內切換）；以及 Codex 是否要把 pinned 和 Q4 的換位排除在連續次數之外（現在算在內）。
- `unrealized` 111 次：名目 set 框不同、實際字框沒動。座位判斷應改用實際的字框，而不是套版的名目框（`seatsDiffer`）。
- 影片核對只量歌詞框的位置，不比較載體和頁面輪廓。page-handoff 換頁但字框位置不變時，會被算成 unrealized。
- 慢歌 6 的目標也沒達到：慢歌片段只有 chalkboard 能做句內切換，其他四個單頁世界只能在句與句之間換。
