## 量法

- 只看計畫。`realizedMoments` 是 `rankMoments` 選出來的數量（**計畫中**），沒有接進 plan，也沒有渲染。Codex §7 要求的同 seed 開／關影片比對留到第二階段；普通 beat 或只有計畫紀錄的時刻，不能算作已實現。
- **API 呼叫 0 次，這是結構上保證的。** 腳本只 import `node:fs`、`node:path`、`node:util`、`node:crypto` 和 repo 裡的純模組，沒有 import 任何網路模組（不用 fetch、http、SDK）。閱讀就是磁碟上的 `meaning.json`，報表記下每份的 sha256：nun `16bfb48f2b49…`、snow `4d09128579f2…`、tsuzuki `2e580e221f09…`、choroin `9d0d50c5ae51…`、tenmon `691d56ecad3f…`（完整值在 `moments.json`）。

## 發現

1. **0 個時刻的真正原因是閱讀快取過期，不是閘門太嚴。** `lineplan.mts:57–61` 遇到已經存在的 `meaning.json` 就直接讀，不會補問新加的欄位。在這個前提下，放寬閘門不會多出任何一個時刻，第二階段接線也不會改變結果。
2. 今天的 `checkMoments()` 有順序相依的問題：它在同一個迴圈裡驗證並套用間距和上限（`signature-moments.ts:266–267`），依歌曲順序處理，所以較早、較弱的候選會把 30 秒內較晚、較好的候選擋掉。測試「is order independent」用同一組輸入重現了這個情形：`checkMoments` 保留較早的那個，`rankMoments` 選較晚、在副歌下拍上的那個。`freeMoments()` 之後又硬性要求副歌和下拍（`free-plan.ts:299`），非副歌的合法候選會直接消失。
3. 新政策不呼叫 `checkMoments()`，因為它的上限寫在驗證迴圈裡，拒絕原因也只是字串。改成用它匯出的同一組基本函式（`wordIndex`、`notWholeWord`、`senseOf`、`hasCall`、`readingSec`、`lastSung`、`MAX_SUNG`、`PAIRED`）逐一重做每個檢查，再由測試「agrees with checkMoments on each single ask」確認：單一候選時，兩邊的語意／完整詞／否定／呼喊判斷結果相同。
4. 演唱時間比今天嚴格：今天只要有 `charStarts` 就算數（`free-plan.ts:292`），政策要求 `charTimed`（對齊器信任的逐字時間，和 Q1 的 `sungWords` 同一個標準）。只有句子邊界時，只有證據詞是這句第一個唱出的詞才接受（at = 句子起點，是真實的起音）；其他情形以 `timing` 拒絕，不用比例時間推算。雙截棍 54 句裡有 35 句是 `charTimed`，53 句有 `charStarts`；換成新標準後可能多淘汰一些候選，第二階段需要量測。

## 契約

**輸入 `MomentInput`**（`moment-policy.ts`）
- `meaning.moments`：唯一的候選來源。沒有閱讀、或閱讀裡沒有 moments，結果是 `reason: 'noMeaningCandidate'`。政策從不讀歌詞來產生候選；`WORD_LISTS` 和 sense 判斷只用來驗證閱讀已經給出的詞。
- `meaningRef`：每個候選都可以追溯到 `${meaningRef}#moments[i]`。
- `cues`（含 `charStarts`、`charTimed`）、`sections`（`type`；`ochi` 由 `analyzeStructure` 標記）、`beats`、`downbeats`、`tempo`。
- `caps: WorldMomentCaps`（草案，見下）。
- `protected: ProtectedEvent[] { id, source: 'Q1'|'Q2'|'Q3'|'Q4', at?, from, to, changesLight? }`：整個占用時窗。adapter 目前放入 Q2 hold（`from..to`）和 Q4 linked handoff（`seam − prepare .. + dur`，`changesLight` 預設 true）。依 Codex §6，Q1 不比 Q5 優先（兩者一起仲裁），Q3 目前還沒有事件。
- `seats`：每句自己的座位框，作為 mini 宣告幾何的基準。

**硬條件（依序檢查，第一個沒過的就是淘汰原因）**：`source`（是閱讀給的 moment 物件）→ `legalCue`（已繪製的 form／variant；1–2 個已知句；echo 和成對 strike 的句型）→ `evidence`（完整詞、在句中、屬於這個 variant 的意思、長度上限、echo 詞）→ `negated` → `why`（非空、可追溯，不是重複詞或 variant 名）→ `timing` → `capability`（世界能畫 big，或有某個 mini 家族能如實承載；scene 必須有一個既有物件與證據詞有關）→ `reading`（被擊的句先讀完；本句有完整閱讀時間）→ `shout`（本句或緊接的重唱帶有呼喊就不碰）→ `collision`（準備＋主動作＋退場＋復原的整個時窗，和每個保護事件之間至少隔 `ACTION_GAP`；big 改變明暗，所以和換光要隔 `LIGHT_GAP`）。big 撞到時改試 mini，**語意動作的 `at` 永遠不移動**。

**排序**：所有候選都先各自驗證，之後才排序。`score = 4·semanticSpecificity + 3·worldFit + 2·musicalFit + readingSlack − repetitionPenalty`，每一項都在 0–1，各項分數都寫進輸出。
- `semanticSpecificity`：只看證據，不捏造信心：基礎 0.4；意思落在詞首 +0.3；`why` 引用了證據詞 +0.2；證據是完整詞組（CJK ≥2 字、拉丁 ≥4 字母）+0.1。
- `worldFit`：scene 1.0，page 0.85，big overlay 0.7，type-only 0.6（提案值）。
- `musicalFit`：副歌下拍 1.0 > 段落轉折（段落第一句）0.7（在下拍上 0.8）> 副歌非下拍 0.55 > 其他下拍 0.45 > 其他起音 0.3。不在副歌、不在重拍都**不會**被淘汰。`ochi` 段裡，留存／收束形式（freeze/stop、echo/ghost、shape/fall、shape/rise、strike/wipe）+0.2，爆點型的分數減半；`ochi` 一律優先用 mini。
- `readingSlack`：閱讀時窗扣掉需要的閱讀時間後剩下的秒數，除以 2，上限 1。
- `repetitionPenalty`：選第二個時才計算。form／variant 相同或證據詞相同為 1；只有 form 相同為 0.6。

**預算**：big 與 mini 合計每首 ≤ `MOMENTS_PER_SONG` = 2；彼此相隔 ≥ `MOMENTS_APART` = 30 秒（從 `signature-moments.ts` import）；每段最多 1 個。沒選上的候選都寫明原因（`notChosen`）。

**變體與幾何**：副歌（非 ochi）且世界允許 big 時先試 big，其他情形先試 mini。mini 的作用區是宣告的框，以本句座位為中心縮放到 15–30 % 畫面（目前取 22.5 %）；主動作 = 一拍，夾在 0.35–0.6 秒；只有準備動作可以吸附到 `at − 0.45 … at − 0.10` 內的拍點，沒有拍點就放在 `at − 0.25`；復原 0.3 秒，算在時窗內。big 的時窗涵蓋整句接管（`actor.start − 0.2` 到下一句或最後一字 +3 秒），再加復原；作用區是整個畫面。

**輸出 `ScheduledMomentCandidate`**（交給 `planWorldEvents()` 的排程候選，Codex §6）：`{ id, kind: 'signature-moment', at, from, to, cueIds, meaningRef, variant, score, changesLight, protectedRegion, render: { family, form, variant, word, prepareAt, mainSec, ownsLines }, fixed: false }`。`world-events.ts` 目前還沒有排程候選的型別，這個物件就是提案的形狀。

**`WorldMomentCaps` 草案**（`moment-caps-draft.ts`，45 個世界全部 `derived`）：`big` = 世界沒有自己的動作（`ownMoves`）→ 43 個世界；document 和 watercolor 沒有 big。`mini` 家族：有 set pieces 的世界有 `scene`，sheet 世界有 `page`，所有世界都有 `type-only`。分布：scene/page/type-only 31、page/type-only 7、scene/type-only 7。`MINI_FORMS` 規定每個家族能如實承載哪些 form；沒有合理對應的就拒絕，不把全螢幕效果縮小貼在角落。

## 第二階段接線（本階段沒有寫）

1. 先用現行 prompt 重讀五首，取得 `moments`（要花 API 費用，需業主核准），固定新 `meaning.json` 的 sha256，再重跑這支腳本，取得真正的淘汰表。
2. `world-events.ts`：新增排程候選的輸入（先保護 Q2／Q4，再仲裁 Q3／Q5 和可選的 Q1）。選不到就試下一個候選，不移動語意起音；核准之後才成為受保護事件。
3. `free-plan.ts::freeMoments()`：只負責把排程器核准的結果轉成 `SignatureMoment`，拿掉自己的副歌／下拍篩選和 `checkMoments` 的順序上限。`freeJob()` 的 `ownCues` 拿掉 fine/hit 的做法只用於 big；**mini 保留正常的歌詞 renderer**，不套整句接管。
4. 渲染：mini 依家族各自實作（page／scene／type-only），在宣告的作用區內進行，全程不遮住正在唱的筆畫。
5. `world-shared.ts`：在 Q1 的 `compositions` 定案後，同一次整合變更把 `WorldMomentCaps` 搬進去，未宣告的世界預設不啟用。
6. 驗收補影片：同 seed 開／關比對（語意動作可辨認、作用區達標、載體完整、閱讀無損）；另外跑無金鑰、無閱讀快取的情形，API 0、時刻 0，正常影片照樣成立。
