# 免費文字版：閱讀優先的字體編排器

日期：2026-10-31　狀態：草案，使用者看過樣片：太單調、頁面記憶看不出效果（改走既有引擎逐句全層搭配，見後續）　分支：feat/lyric-editing

標示：**已驗證** = 讀程式或實測確認；**推論** = 未實測；**我的決定** = 使用者沒指定、由我先定，可推翻。

## 1. 為什麼做

使用者要三件事：自己做文字動態、免費直出版當付費入口、免費版也要稍微貼合歌詞。成品要看得出不是抄來的。

JIZURA（免費瀏覽器工具）的強項是手感與「字就是畫面」。弱點是不懂歌詞、沒有全曲起伏、沒有故事。我們的強項是導演判斷，弱點是字常退成字幕。

## 2. 目標與非目標

目標：
- 字成為畫面主體，且一次聽就讀得完。
- 免費版每首成本趨近零，在瀏覽器本機完成。
- 免費版有限度貼合歌詞。付費版仍明顯更好。

非目標：
- 不移植、不改寫對方程式，不追求零件數量。
- 不做逐句語意特效，不強制故事。
- 第一版不做 AE、綠幕、多比例輸出。

反目標（即使功能完成也算失敗）：
- 字還是小字幕，只有背景熱鬧。
- 看起來像 JIZURA 換色。
- 免費版比付費文字版好看，或手機上做不完。

## 3. 診斷

**已驗證**：我們已有 28 種進場、18 種退場、9 種停留（`treatment.ts`），也有閱讀時間修正、`koma` 步進與 hold 漂移（`engine.ts`、`runtime.ts`）。差距不在招式數量。

**推論**：`typeplan.mts` 以 shot 選歌詞 template、背景 cut 另外排，所以可能背景切得熱鬧、歌詞構圖不換。需用目前版本重做同段基準才能定案，影格比對用的是 10-21 版。

## 4. 設計

### 4.1 閱讀優先的時間預算

每個閱讀片段分配「進場 + 可讀停留 + 退場」。時間不足時依序取消次要動作、stagger、進退場，最後才合併片段，閱讀時間不可壓縮。動作秒數有上限，長句得到的是更長的停留。stagger 用固定總時窗。

靜止是允許的。慢歌的變化來自構圖、位置與留白，不靠鏡頭或逐字晃動補滿。

### 4.2 構圖

一句是一張構圖，由語意決定主次、大小與留白。可以片段放大，但整句要同時可讀，除非有可信的短語邊界。超框先重新斷行，不擠扁 CJK。

### 4.3 頁面記憶（我們的簽名，需樣片驗證）

歌曲的一段是一頁。句子佔頁面上的位置，離開時只留非文字痕跡，不留可讀舊句。歌詞回返時回到同一位置。狀態由事件與絕對時間推導，可任意跳轉。

若樣片看不出價值就刪除，不為差異化保留負擔。

### 4.4 語意

一次 Haiku 5.5 呼叫（價格為每百萬 token 輸入 $0.10、輸出 $0.50，估每首約 US$0.0015，未含重試與流量）。輸出段落的張力、釋放、距離、延續與重點，附原文證據與信心。動作由我們的規則選，不由模型點特效。

- 模型只能引用既有 cueId 與文字區間，不可改寫歌詞。
- 整首語意動作上限 2 個，預設沒有，且不得破壞字形。
- 驗證失敗或無網路時退回規則版。
- 設每首 token 與重試上限、全站支出上限。

### 4.5 免費與付費

| | 免費 | 付費 |
|---|---|---|
| 動作核心 | 共用 | 共用，舊片不重算 |
| 時間 | 使用者點拍或貼 LRC，只有行時間 | 人聲對齊、逐字時間 |
| 語意 | 段落層級，有限 | 導演、概念確認、跨段因果 |
| 畫面 | 字與單一風格 | 角色、圖片、故事 |
| 輸出 | 本機 720p，有浮水印 | 1080p，修正服務 |

### 4.6 技術

Codex 建議產品用精簡 Three.js profile，重用 `phrases.ts`、`render/glyphs.ts`、`render/layouts.ts`、`render/runtime.ts`、`structure.ts`。樣片用 Canvas2D 只因為它是拋棄式。產品路線待樣片後比較效能再定。

匯出要新做：`renderAt` 接 WebCodecs，另需音訊與 MP4 封裝。**已驗證**：repo 目前沒有 WebCodecs encoder，現有 `preview-export.service.ts` 不能直接當正式輸出。字型需自行託管分片，不走 Google `text=`。

## 5. 不抄的做法

- 讀對方原始碼的是獨立子代理，只產出原理筆記。實作者只看我們的規格。
- 主對話曾讀過對方約 200 行程式片段（動畫配方開頭、緩動列表、渲染器開頭），設計者並非完全未接觸。
- 預設不用：黑底配彩色邊加顆粒、攝影機 HUD、座標圓、引線註解、條碼計數、歌詞牆、筆畫飛入組字，以及時間延遲的彩色殘影。免費 profile 也關掉我們引擎既有的殘影（`engine.ts:1741`）。
- 每個 technique 記錄實際來源、設計理由與評審結果。免費集合拒絕未登錄項目，並審查組合長相。
- 畫面能支持「有自己的設計語言」，無法證明「沒有參考過」。對外不宣稱無接觸，內部紀錄如實保存。

## 6. 驗證

樣片：大雪與雙截棍，各做 A（閱讀編排）與 AB（加頁面記憶）。語意人工填，先驗呈現不驗模型。

| 檢查 | 通過條件 |
|---|---|
| 歌詞清晰 | 全幀零黏合、零裁字、零遮字，手機播放可讀 |
| 文字時機 | 空唱區無可讀歌詞，無舊句誤認 |
| 字成為畫面 | 使用者能指出至少三次有理由的構圖變化 |
| 頁面記憶 | 使用者看得出回返呼應，閱讀不比 A 差 |
| 不像別人 | 使用者與盲評者不會聯想到 JIZURA |

### 6.2 使用者決定與新方向（2026-10-31）

使用者看完樣片：太單調、頁面記憶看不出效果、差距很大，應該用我們既有手法讓每句都有完整搭配。因此刪除 §4.3 頁面記憶與 Canvas 路線，改走 `lineplan` 規則編排器加既有引擎。

**已驗證**的根因：版型是逐鏡頭選（雙截棍 54 句只有 30 個鏡頭，29 句同一種 slam），背景運鏡不帶動歌詞。新增 `render/text-cam.ts` 與 `CueStyle.textCam`，只有編排器會設定，舊流程不受影響。

### 6.3 付費導演的判斷（2026-10-31，使用者要求）

一句拆多鏡不是每首歌、每句都要用。付費導演要讀整首歌，判斷哪些段落適合拆鏡、哪些該整句停住，並寫下理由。免費版的規則編排不做這個判斷。接導演時，`build-cut` 與新手法要帶適用條件進 prompt，不可當預設。

### 6.4 上線條件與後續工作（2026-10-31，使用者確認）

使用者擔心付費語言做出來比免費版差。這是真實風險：新手法目前只給免費編排器。

1. 先學完待辦 72 項（`docs/research/2026-10-31-jizura-backlog.md`）。
2. 免費版上線前，先升級付費導演：逐句搭配，判斷哪裡拆鏡、哪裡停住，並使用新手法。
3. 對照關卡：同歌同段比較免費版與文字動態版，付費版要明顯較好才能開放免費版。
4. 語言分批升級：先 5 種已驗證，再看待驗證語言，逐一確認新動態是否相配。
5. 插圖版、故事版開放前，歌詞運鏡與字級變化要納入道具避讓。
6. 一鍵換版時一起做風格：不另創風格，由語言抽出輕量版（配色、字型、材質、手法偏好）。先 5 種已驗證，待驗證的要通過多次隨機抽樣；擱置與依賴場景圖的不做。起步 5 到 10 種即可。

### 6.5 每首歌的手法變化（2026-10-31，使用者確認保留）

既有 `knobs.ts`／`songVary` 由歌名與活潑度決定每招的數量、大小與速度，免費與付費都自動生效。升級付費導演時，再讓導演依歌詞指定重要手法的參數，例如流星數量。

### 6.6 付費逐句導演（2026-11-01 實作，選用開關）

新腳本 `scripts/lyric-vj/linedirect.mts`，規則在 `linedirect-core.mts`。現有付費流程不呼叫它，`make.sh` 預設不變，要用時手動跑（見檔頭）。

- **輸入**：付費版的語言、配色、字型、世界（backdrops）、段落（`typeplan.json`、`base/treatment.json`）。
- **輸出**：`--plan` 同形狀的 plan，每句帶 layout、enter、idle、exit、裝飾、拆或停、理由（`lines[].direct`、`decisions.json`）。歌詞與空唱段落的世界照付費版的時間點沿用，空唱鏡頭保留付費導演原本的刀。
- **守門**：與編排器共用閱讀預算、字級下限、詞界、風格份量。不合格的選擇退回編排器該句的選擇，記在 `fallbacks.log`；版面、進場、停留任一不合格整句退回，退場、裝飾、背景只退該項。渲染後 `--metrics` 可再把字級或閱讀不過的句子退回，不必再呼叫 API。
- **手法條件**：只有規則能到的手法（B40、B43–B46、B50）與只有語意能到的（B49、B56、B60）都列在 prompt 並附條件，歌詞不含規則詞時要引用 evidence。
- **永遠排除**：HUD、座標與假資料（counter、measure、chart、progress）、RGB 色散（`lineDirect` 關 chroma 通道）、筆畫組字（`pieces`、`gather`）、歌詞牆，以及角落的文件計數（`document` 關閉，我的決定，由 fine tier 取代）。
- **歌詞參數**：`tune` 只開放「數量」類 knob（流星、星點、雨、星芒等），經 `kn()` 夾在原本範圍內。
- **渲染差異**：`design.lineDirect` 只有這條路徑會設，保留語言的 keyline 與對比重建；背景動作的 hush 在有 backdrop 時回到 backdrop，不鋪平紙。

**未解決**：尚未接進 `make.sh`，也未接網站。導演 prompt 改過一次（加入主從與字數限制），只有チョロイン用新版重跑。

### 6.7 瀏覽器即時生成（2026-11-01 實作，本機，未開放）

- **規則核心**：`src/app/lyric-vj/lineplan-core.ts`（`scripts/lyric-vj/lineplan-core.mts` 轉出），瀏覽器與腳本共用。
- **計畫到 job**：`free-plan.ts` 的 `freeJob`，對編排器計畫等於 `typeplan.mts --plan`，五首 treatment 完全相同（`scripts/lyric-vj/free-plan.check.mts`）。付費腳本沒改。
- **換版**：`composePlan(..., { reroll })`。不帶 reroll 時計畫一字不差。
- **逐句建置**：`job.live`，只對編排器計畫生效。離線預設仍全部先建。
- **預覽與匯出**：`render/live.ts`、`render/export.ts`。依賴 `mp4-muxer`。
- **風格**：`free-styles.ts`，六種，全部出自 5 種已驗證語言。
- **入口**：`/free`，只在開發建置出現（`isDevMode()`），資料來自唯讀的 `scripts/lyric-vj/free-local.mts`，`ng serve` 的 proxy 轉 `/free-data`。

**未解決**：字型仍走 Google Fonts，正式版要自行託管分片（§4.6）；浮水印（§4.5）未做；貼歌詞時拍點是均勻假拍；手機未測。

### 6.7 方案調整（2026-11-01，使用者決定）

看完 A/B 與專屬時刻測試後，使用者決定改方案方向：

1. 免費版取代文字動態版，維持整首，720p、浮水印。
2. 插圖版與故事版都要使用這次新做的文字動態（逐句編排與新手法），再加各自的插圖、專屬時刻與設計。
3. 專屬時刻疊在完整編排上，不拿掉背景、編框與裝飾。

上線條件改為：免費版不比現行文字版差，且插圖版明顯勝過免費版。

插圖版、故事版接入前要先解決：道具避讓納入歌詞運鏡與字級變化；紙藝背景與插圖背景不可互相打架；`linedirect` 接進 `make.sh`，並確認修正流程（replan、fix）仍可用。

### 6.8 46 種風格全開（2026-11-01，使用者決定）

免費與付費都提供全部 46 種風格，含待驗證與原本擱置的語言，全部要提升品質，做到和 JIZURA 一樣有鮮明特色。此決定取代 §6.4 第 4、6 點的分批與「起步 5 到 10 種」。

研究方式：使用者已同意閱讀 JIZURA 原始碼作參考（2026-11-01），不可照抄程式或視覺，取代先前只看輸出畫面的做法。每種風格要有自己的字型、材質、配色、版型、進退場、裝飾與背景，不是同一套換配色。原本依賴場景圖的語言，要先改成純程式可畫的版本才算數。

### 6.9 免費版歌詞時間（2026-11-01，使用者決定）

免費版不跑伺服器對齊：匯入 LRC、瀏覽器查公開歌詞庫、手動打拍同步，加瀏覽器拍點偵測，全部在使用者端。自動逐字對齊留給付費版作為賣點。

### 6.10 浮水印與上線範圍（2026-11-02）

免費版畫面內不加浮水印：JIZURA 沒有，加了會輸在第一印象。片尾也不署名（2026-11-02 決定：JIZURA 沒有，署名只會把人推去用沒有署名的工具），720p，不含專屬時刻與插圖。此決定取代 §6.7 第 1 點的浮水印。上線第一版用已完成的風格，不等滿 46 種。

## 7. 建置順序

1. S：定義 `TypePlan`、閱讀規則、來源白名單。
2. M：樣片比較，決定頁面記憶去留。
3. M：抽出片段排版與時間預算，補單元測試。
4. M：頁面記憶，若通過。
5. L：瀏覽器 profile、字型分片、快取釋放、WebCodecs 封裝、手機儲存。
6. M：Haiku 語意計畫、驗證、費用上限、退回。
7. M：快歌、慢歌、長句、多語回歸，付費共用新核心。

## 8. 最可能失敗的方式

1. 沒有短語時間卻硬切詞，字和歌錯拍。
2. 頁面記憶變成舊歌詞堆積。
3. 語意模型變成動詞特效配對。
4. 組合長相仍像同一來源。
5. 桌面好看，手機字型、記憶體或匯出拖垮完成率。
